### Offline verification and access enforcement

The installed Harbor implementation was inspected: it supports a separate verifier,
sidecar collect hooks after the main container stops, and re-materialized artifacts
at their original source paths. Its agent publish directory is mounted only at its
mirrored artifact location, not the trusted artifact root.

That support now feeds an offline `bench-verify` executable one atomically captured
world-evidence bundle. Expected contracts, scenario identity, and the verifier image
stay outside the model environment. The grader credential is present only in the
world container, where the collect hook uses it after the agent phase. The separate
verifier has no network, MCP configuration, or admin credential.

- `verification.json` hashes the actual input bytes. `assessment.json` and numeric
  `reward.json` come from the same assessment; journal/events/state diagnostics are
  derived from the same bundle.
- Missing, malformed, incompatible, or cross-task evidence fails closed. Contract
  errors and failed answer collection have explicit, distinct outcomes.
- Frontend and backend networks are separated. A real Docker probe nevertheless
  reached the backend's known IP across bridges. The implementation therefore
  enforces actual peer identity inside the world before HTTP and TLS dispatch;
  forwarded headers cannot confer access.
- Denied API calls remain journaled and cannot mutate data or advance business
  time. Caller-resolution failures emit structured environment-failure events and
  cannot be mislabeled ordinary task failures.
- Admin routes require the tools origin except for world-local collection/health;
  sensitive routes still require the credential. Direct-access tracks explicitly
  receive a backend route and omit the API-origin restriction.
- Generated tasks require `offline-world-evidence-v1`. Scored compose rejects
  missing credentials rather than defaulting to open admin access.
- `deploy/test-task-isolation.sh` tests actual routing, secrets/hidden files, main
  shutdown, and forged evidence/reward files. Oracle runner unit probes separately
  reject invalid no-op assessments, missing metadata, malformed rewards, and runner
  failures rather than counting every reward zero as a valid no-op result.

### Evaluator revision 4 finalization checkpoint

World finalization is now implemented in evaluator revision 4 / evidence schema 2,
under `offline-world-evidence-v2`. Admission closes before collection; request
ownership and explicitly retained background execution ownership drain before
sealing. Cancellation has terminal evidence without pretending its work succeeded;
retained/released execution events prove that canceled responses did not hide live
blocking workers. The actual Cloudflare blocking path retains ownership before
dispatch, including queued work.

Sealed evidence independently validates event identity, reset generation, execution
ownership, complete capture, and terminal closure even for version-1 task contracts.
Timeout is a persistent environment failure; normal completion afterwards cannot
erase it. The first collector's 20-second window and actual drain timing are recorded
separately from business time. New requests, answer replacement, and reset cannot
reopen a closed attempt. This is not yet proof of successful external harness shutdown
or full workflow-budget accounting.

The collector-cancellation deadline race is also closed. The original window is
enforced when work releases its ownership, even if the collector future was dropped.
An on-time completion retains its actual duration when collected later; a late
completion cannot become a passing retry. Virtual-time regressions cover both cases
without changing the host clock.

### Evaluator revision 5 request evidence

The canceled-forbidden-attempt blind spot is fixed at the request-observation seam.
Owned operations capture heads and complete bodies before handler dispatch; completed
journal entries derive their request fields from those observations. Path/method,
query, and argument prohibitions survive cancellation without fabricating a response
or allowing an unreceived body to masquerade as null.

Permanent regressions cover the original counterexample, canceled query/body matches,
required-call non-acceptance, response-status conditions, duplicate evidence references,
and malformed/conflicting receipts. The original synthetic probe now returns reward 0
with `forbidden_calls_ok = false` and `environment_ok = true`; its revision-5 artifacts
are `/tmp/tool-bench-e5-forbidden-abort.2ntriina`.

Request bodies retain exact UTF-8 or binary bytes. Known synthetic credentials become
service/header-scoped references and digests; unknown credentials/custom headers are
hashed rather than stored verbatim. The catalog explicitly declares fixture headers,
resolves only its own static fixture environment values, and rejects policy typos or
inert/malformed declarations. Both image-source hashes now include that catalog.

Replay preflights complete context before executing anything, hydrates only compatible
fixture references, preserves raw bodies and duplicate public headers, and does not
follow redirects automatically. Missing legacy context, redacted unknown values,
unsupported services/nonserial ordering, and orphaned internal requests are distinct
from backend response mismatches. This is not general concurrent-scheduler replay or
complete support for every possible credential/header shape.

The native Firecrawl regression reproduces its authenticated 403/200 sequence without
recording the raw key, fixing the previously observed replay failure for new journals.
Older journals remain explicitly non-replayable under the strict player rather than
being silently authenticated with invented credentials. Evidence schema 3 and
`offline-world-evidence-v3` distinguish this revision from earlier runs.

### Revision 6 clock refinement

Business time now defaults to a fixed scenario reference. Transport-driven stepping
is retained only under the explicit `legacy_transport` condition. Snapshot/task
metadata declares the policy, and the verifier checks reference-time consistency.
Negative steps fail authoring and checked advances prevent overflow.

Cloudflare Code Mode uses the same reference for `Date.now()`, callable `Date()`,
and implicit date construction; explicit dates, parsing, UTC, branding, and subclass
behavior have dedicated regression coverage. Atlas pending cluster changes progress
on scoped status observations instead of unrelated transport traffic or global time.

failures in the new clock invariance/Date regressions. Those expectations are being

remaining timestamp expectation. Log ordering now uses newest insertion order for

versions without advancing business time. Dedicated regressions cover those cases.
